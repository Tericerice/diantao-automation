## 结论

## 优先问题

P1：直接影响执行正确性、停止能力或点击对象。P2：条件性缺陷、维护和测试缺口。全部未修复。

### 01 / P1：视频有次数计划，但到时间会漏滑并报成功

位置：u2_scanner.py:1208、1210、1225、1230、1243。

循环先检查时间上限，到时直接退出；滑动异常也会增加 swipe_index，最终统一 True。没有检查计划是否完成。

隔离复现：60秒，固定选中基础8次+额外7次，共15次。零延迟设备调用15次；每次 swipe 消耗8秒的模拟设备只调用8次，仍返回成功。

建议保留次数、首滑和间隔参数，区分计划完成、设备异常、保护超时。保护超时可以结束执行，但不能记为次数完成。还需检查长调用后是否为追赶绝对时间表而连续补滑。不能用“更快”替代用户要求的间隔。

### 02 / P1：两个调度入口的超时与执行语义不一致

位置：全部执行.py:143、155；任务选择器.py:290、323；全部执行.py:277。

CLI 在阻塞式 readline 前检查超时；子进程没有完整日志行时无法继续检查超时及停止标记。异常分支缺少统一进程回收。GUI 虽保存和显示 timeout，执行代码没有使用它，逐行读取后也无超时 wait。

隔离复现：本地子脚本只 sleep(3)，timeout=1，约3.94秒后才返回超时。没有设备调用。

CLI 还会追加两轮复扫，GUI 只跑一次选中列表。GUI 停止后立即开放“开始”，没有确认旧 worker 退出，快速停止/重启时共享 stop_flag/current_process 存在竞态风险（静态发现，未操作GUI复现）。

建议共享子进程启动、日志、超时、取消、回收、结果；UI/CLI只负责展示。保留任务顺序、间隔及复扫计划，不因合并而强制改变入口语义。旧 worker 退出后再开放新一轮。

### 03 / P1：watcher 暂停不覆盖所有连接和视频调用路径

位置：u2_scanner.py:81、114、124；utils.py:442、456；各视频调用方。

U2连接器启动 ctx，却未写入 d._global_watcher_ctx；暂停函数只查该属性。utils.connect_device 则保存句柄，同名连接函数行为不同。走路使用 utils 连接且显式暂停/恢复，签到、打工、睡觉、额外元宝等没有完整保护。

隔离复现：通过 U2 连接函数创建模拟 watcher，再调用 pause_global_watcher，仍 started=True，设备没有句柄。

建议统一句柄持有和观看阶段保护，finally恢复；保留 U2 特有的覆盖层及操作延迟设置，不能简单用另一同名连接函数覆盖。嵌套调用还应保留进入前的暂停状态。

### 04 / P1：购物直播仍可被“即将完成”立即结束

位置：点淘购物赚钱.py:177、200、224。

独立直播循环把“即将完成”“已完成”“恭喜”当提前退出信号，没有最低观看时长门槛，与公共直播保持要求时长的行为不同。倒计时消失分支又是在同一份OCR里先找到倒计时，再检查是否不存在，条件不可成立。

隔离复现：要求60秒，模拟OCR仅“即将完成”，进入观看计时后0秒就结束。入口等待不等于已完成观看。

建议共享最低时长判断，保留购物媒体识别兜底、每十秒滑动及返回方式，不直接替换执行器而顺带改变参数。

### 05 / P1：两处连续无任务退出无法累计

位置：元宝中心小任务.py:272、283、286、325；淘金币任务.py:434。

元宝中心在OCR有文本时立即清空 prev_empty，随后无任务分支追加；下轮再清空，达不到三轮。OCR完全空白分支又在辅助函数及调用方各追加一次，可能两轮就达到三次计数。

淘金币在控件树有节点时将 empty_times 清零，发现无任务再加一；页面有普通文本时永远达不到三次。

隔离复现：两份原循环分别输入四轮“有文本、无任务”，均仍在循环，由观察器终止。

建议区分扫描失败、扫描成功但无任务，每轮只计一次。保留元宝中心“不因相同任务列表而退出”的明确历史要求。

### 06 / P1：自动发现会默认勾选工具和持续运行脚本

位置：任务选择器.py:20、40、163；task_config.json。

排除词未涵盖 debug、calibrate、u2_scanner、RAG模块、1024等，新文件默认 checked=True。当前配置已经勾选多个此类文件。打工加速是当前页持续等待模式，也在批量配置中。

配置中的 ../coin11-tb-main/2026淘宝618活动.py 不存在。赚钱卡和额外元宝尚未注册在保存配置中，但GUI再扫描可能自动勾选新增脚本；额外元宝为无限扫描入口，不应自动放入普通一次性流水线。

建议明确注册一次性任务、持续监控和调试工具，新任务不自动参与批量。保留持续监控的无限等待需求，不为批量跑完而删掉其功能。

### 07 / P1：识别不了任务身份仍可能点击

位置：点淘购物赚钱.py:284、299、411；元宝中心小任务.py:185、248；点淘鸭钻石任务.py:280、295。

购物配对不到名称默认 browse60秒，末端只对非空名称查黑名单。元宝中心配对失败退成“去完成”，由other分支点击。钻石二次校验只确认附近存在按钮，不确认对应任务身份，失败仍继续点击。

未知任务不是增加几个黑名单词就能覆盖的。钻石还在多次直播进度循环中复用原按钮坐标，页面变化后可能失效。

建议把无法确认对象与普通浏览分开，重扫确认身份后再执行；保留黑白名单，不自动放宽白名单。

### 08 / P1：直播调用契约存在缺口

位置：618花花乐.py:84、136；签到赢元宝.py:528；u2_scanner.py:917、1031。

618直播分支没有点击入口或返回，上层只调用 do_task，公共直播也不点击/返回。因此可能在任务列表等待、滑动，随后仍把任务加入done。这是静态调用链缺口。

赚钱卡分支点击后不执行普通签到 exec_live 中的 back；公共直播也不返回。如果页面不自行关闭，下轮就在直播页扫描。该页面是否自动返回尚未真机验证，不能直接按旧规范补删back。

建议分别用“入口一次、预期页面停留、回到正确列表”的动作序列测试核对，再局部修复，不全仓统一返回次数。

### 09 / P1：1024 引擎向下移动计算成向上

位置：diantao_1024_auto.py:332。

转置后翻转行再调用move_left，没有反转需要合并的行内方向，计算结果与上移一致，AI预测和实际下滑不同。

隔离复现：4×4棋盘只有左上角一个1，下移应到左下角，原函数返回仍在左上角。只运行原GameEngine，没有ADB。

建议单独修正方向变换，用四方向独立预期结果测试；保留 n+n=n+1、启发式权重、生成概率及校准参数。

## 次优先问题

### 10 / P2：成功、结束与失败混为一谈

- utils.py:727、u2_scanner.py:1377 固定浏览分支超时仍统一True。模拟要求60秒、max_wait=5，两套实现约6.5秒都返回True。实际调用通常传更大上限，但接口不符合其超时False声明。
- 固定浏览while要求未达min_duration，内部完成分支却要求elapsed>=min_duration，基本不可达，不能当成有效收尾覆盖。
- 公共直播返回的是completion_detected，不等于已满足停留时长；多数调用方忽略结果直接加完成计数，浏览False也经常被忽略。
- 多个脚本捕获异常只打印，不设置失败退出码；导航失败正常return也可能被调度器计为成功。

建议先定义动作结束、确认完成、无任务、失败、取消的结果含义，再用于日志和调度，不需要先改活动算法。

### 11 / P2：行聚类、进度及次数限制不一致

位置：点淘鸭钻石任务.py:169、177、209、314。

聚类比较相邻块而非整行跨度。cy=100/150/200、容忍度60会被聚成同一行，跨度100，可能重现历史跨行配对。

扫描允许全角括号进度，parse_progress只接受半角；“看直播60秒（2/5）”返回None。半角进度cur>=total时又从0执行整轮。MAX_CLICK限制do_task调用，不限制内部直播次数，key还包含变化进度。

建议增加页面样本、全半角及已完成边界测试。不要把直播剩余次数、MAX_CLICK=2与总任务数合成一个参数。

### 12 / P2：公共黑名单修补未覆盖全部路径

位置：utils.py:959、u2_scanner.py:413及多个活动本地规则。

utils支持移除空白/零宽字符，其他同名函数与本地判断未完整同步。“浏览元宝\u200b商城”在utils被拦截，在u2_scanner未拦截；现有黑名单测试只覆盖utils。

建议共享文本清洗和共同禁用规则，保留活动额外黑名单、白名单及优先级；不能取各列表交集而丢掉限制。

### 13 / P2：导航失败没有阻止后续动作

位置：u2_scanner.py:478、497、510、523；一键下滑.py:271；淘金币任务.py:387。

navigate_chain找不到控件仍继续，若干导航固定True。一键下滑忽略导航结果，即使打印“跳过该轮”仍滑动。淘金币返回五次失败仍True。

绝对坐标可能是用户实测约束，不能一概比例化。应让失败导航阻止后续操作，并明确坐标适用的分辨率/页面版本；猜价格X=1179等也需要其设备前提。

### 14 / P2：依赖与测试边界不足以支持直接重构

- 没有依赖声明或锁文件，设备、截图、OCR、GUI、服务环境未区分。
- 业务文件大多顶层connect_device，普通import即产生连接/watcher副作用。测试因此常抽AST或替换sys.modules，未覆盖完整启动链。
