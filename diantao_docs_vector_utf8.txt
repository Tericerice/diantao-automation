# 点淘自动化项目架构文档

## 项目概述

本项目是面向点淘（`com.taobao.live`）和少量淘宝系任务页的 Android 自动化脚本集合。当前主线是 **Python + uiautomator2 + 云端 PaddleOCR + ADB 截图**，并保留 OpenCV 模板匹配、LightRAG 开发规范查询、GUI/CLI 调度器等辅助能力。

截至 2026-06-27，`diantao/` 是活跃主项目目录；`hamibot.diantao/` 在当前工作区未发现，相关文档仅作为历史/备用实现说明。

## 当前核心流程

```text
任务选择器.py / 全部执行.py
        │
        ▼
读取 task_config.json 中已勾选脚本
        │
        ▼
逐个启动业务脚本（超时、日志、Ctrl+C 停止）
        │
        ▼
connect_device() 连接真机并启动弹窗 watcher
        │
        ├── U2 hierarchy / textContains 定位
        ├── 云端 PaddleOCR 识别 WebView/图片文字
        ├── ADB screencap 兜底截图
        └── 坐标盲点 / OpenCV 模板匹配兜底
        │
        ▼
导航任务页 → 扫描按钮/气泡 → 黑白名单过滤 → 执行任务
        │
        ▼
返回任务页 / 写 task_log.json / 进入下一个脚本
```

# A：点淘核心任务脚本（`diantao/`）

## 概述

`diantao/` 是当前活跃主目录，业务脚本直接导入 `u2_scanner.py` 和 `utils.py`。当前实现已经不是“业务脚本 → 薄层转发器 → AGENT 工具”的结构，而是：

```text
业务脚本
  ├── u2_scanner.py：纯 U2 任务扫描、导航、执行器、结束判断
  └── utils.py：云端 OCR、ADB 截图、通用工具、日志、RAG 查询、部分委托入口
```

## 通用依赖调用链

```text
业务脚本
  │
  ├── connect_device()
  │     ├── adb devices 选择设备
  │     ├── u2.connect()
  │     └── watch_context 自动处理确认/关闭/刷新等弹窗
  │
  ├── 页面定位
  │     ├── U2 textContains / hierarchy
  │     ├── scan_page()
  │     ├── get_ocr_text_blocks() 云端 OCR
  │     └── get_ocr_text_blocks_adb() ADB 截图 OCR 兜底
  │
  ├── 任务执行器
  │     ├── execute_browse_task() / browse_task()
  │     ├── execute_live_task()
  │     ├── execute_video_task()
  │     ├── handle_guess_price_game()
  │     └── click_three_selected_items()
  │
  └── 日志/汇总
        ├── log_task_completed()
        └── show_today_summary()
```

## 任务类型分流

| 类型 | 典型关键词 | 执行器 |
|---|---|---|
| 浏览类 | 浏览精选、猜你喜欢、逛一逛、滑动浏览 | `execute_browse_task()` 或 `utils.browse_task()` |
| 直播类 | 看直播、看福利直播、看黄金档 | `execute_live_task()` |
| 视频类 | 看视频、短视频 | `execute_video_task()` |
| 猜价格 | 猜价格、猜价格游戏 | `handle_guess_price_game()` |
| 精选宝贝 | 查看3个、看3个、精选宝贝 | `click_three_selected_items()` |
| 气泡收集 | 睡觉/签到气泡、浮动气泡 | `find_bubble()`、`scan_float_bubbles()`、`click_float_bubbles()` |

## 黑白名单策略

- 通用黑名单集中在 `utils.py` 和部分脚本本地常量中，核心是拦截邀请、下单、购买、充值、付款、小游戏、外部 App 引流等任务。
- “含 `猜` 但不含 `猜价格/猜价格游戏`”一般视为危险任务并跳过。
- 点淘鸭、走路等页面使用白名单，只执行明确允许的直播/浏览类任务。

## 结束条件

常见结束判断包括：

- 连续多轮任务列表快照相同：`is_stale_task_list()`
- 连续多轮没有按钮：`is_stale_no_buttons()`
- OCR 无候选任务达到阈值
- 活动页无新任务或已执行任务去重后为空
- 单任务执行超时，由脚本内部或调度器兜底

## 重要变更记录

- `diantao/u2_scanner.py` 当前是完整实现，包含 `connect_device()`、`u2_find_task_buttons()`、`navigate_to_sleep_page()`、`navigate_to_dagong_page()`、`navigate_to_duck_page()`、`execute_live_task()`、`execute_video_task()`、`execute_browse_task()` 等。
- `utils.py` 当前承担云端 OCR、ADB 截图、模板匹配、App 状态、日志和 LightRAG 查询，不只是“任务日志、战报”工具。
- 旧的百炼 OCR 客户端文件在当前目录未发现，文档不再引用它作为主线。

# B：执行调度系统（`任务选择器.py` + `全部执行.py`）

## 概述

当前调度主线由两个文件组成：

1. `任务选择器.py`：Tkinter GUI，扫描脚本、勾选、排序、设置超时、保存 `task_config.json`，也可以直接运行选中任务。
2. `全部执行.py`：CLI 调度器，读取 `task_config.json` 中 `checked=true` 的任务，按顺序逐个执行并写入 `logs/`。

旧文档中的 `定时计划.py`、`定时任务配置.json`、`定时计划.bat` 在当前 `diantao/` 目录未发现；不要再视为当前调度入口。

## `任务选择器.py`

### 功能

- 扫描 `diantao/` 下可执行 `.py` 脚本。
- 排除调试、工具和调度器自身：`调试`、`点击`、`utils`、`全部执行`、`任务选择器`、`__pycache__`、`test`。
- 支持上移、下移、置顶、置底、全选、取消全选。
- 每个任务可配置 timeout。
- 保存配置到 `task_config.json`。
- 可直接在 GUI 中串行运行选中任务，并实时显示日志。
- 附加外部任务：`../coin11-tb-main/2026淘宝618活动.py`。

### 默认超时

| 任务 | 默认超时 |
|---|---:|
| `主播打卡粉丝礼` | 2100 秒 |
| `点淘购物赚钱` | 2100 秒 |
| `睡觉赚元宝` | 3600 秒 |
| `点淘鸭钻石任务` | 2100 秒 |
| `打工得体力` | 3600 秒 |
| `618花花乐` | 2100 秒 |
| `2026淘宝618活动` | 2100 秒 |
| `签到赢元宝` | 2100 秒 |
| `走路赚元宝` | 600 秒 |
| 名称包含 `点淘鸭` 的任务 | 2100 秒 |
| 其他脚本 | 600 秒 |

## `task_config.json`

由 `任务选择器.py` 生成，`全部执行.py` 读取。格式是任务对象数组：

```json
[
  {
    "name": "签到赢元宝",
    "file": "签到赢元宝.py",
    "timeout": 2100,
    "checked": true
  }
]
```

当前目录未发现现成 `task_config.json` 时，先运行 `任务选择器.py` 生成配置。

## `全部执行.py`

### 功能

- 读取 `task_config.json`。
- 只执行 `checked=true` 的任务。
- 每个任务以 `subprocess.Popen([sys.executable, "-u", filepath])` 启动。
- 设置 `PYTHONIOENCODING=utf-8`，实时读取并缩进输出子进程日志。
- 超过任务 timeout 后 `kill()` 子进程。
- Ctrl+C 第一次设置停止标记并优雅退出，第二次强制退出。
- 执行结果保存到 `diantao/logs/run_YYYY-MM-DD_HHMMSS.log`。

### 执行流程

```text
全部执行.py 启动
  │
  ├── load_task_config()
  │     └── 读取 task_config.json，筛选 checked 任务
  │
  ├── 打印待执行任务、文件和超时
  │
  ├── 3 秒倒计时
  │
  ├── 逐个 run_task()
  │     ├── 检查脚本存在
  │     ├── 子进程实时输出
  │     ├── timeout/stop_flag 兜底 kill
  │     └── 返回 name/success/elapsed
  │
  ├── 汇总成功数和耗时
  │
  └── save_run_log()
```

## 调度注意事项

- 调度器不会自动生成 `task_config.json`，配置生成由 GUI 负责。
- 当前执行方式是串行，不并发。
- 调度器不负责设备连接；每个业务脚本自行调用 `connect_device()`。
- `run_task()` 中外部路径检查有一段备用逻辑，但主路径仍以 `SCRIPT_DIR + file` 为准。

# C：OCR 与图像识别引擎（`utils.py` + `tools/`）

## 概述

当前主线 OCR 不再是旧文档里的阿里百炼 `bailian_api.py`。截至 2026-06-27，`diantao/` 目录中未发现 `bailian_api.py`、`ocr_config.json`、`bailian_config.json`。

当前 OCR 主线在 `diantao/utils.py`：

- `OCR_SERVER_URL = "http://175.178.17.23:8888/predict_ocr"`
- 截图压缩为 JPEG 后发往云端 PaddleOCRv4 服务。
- 返回结构化文本块：`{"text": str, "cx": int, "cy": int, "conf": float}`。

## OCR 调用链

```text
业务脚本
  │
  ├── get_ocr_text_blocks(device)
  │     ├── device.screenshot()
  │     ├── JPEG quality=70
  │     └── POST OCR_SERVER_URL
  │
  └── get_ocr_text_blocks_adb(device)
        ├── adb exec-out screencap -p
        ├── PIL 解码
        └── POST OCR_SERVER_URL
```

## 核心函数

| 函数 | 位置 | 说明 |
|---|---|---|
| `_cloud_ocr(screenshot_pil, retries=3)` | `utils.py` | 调用云端 OCR，过滤空文本和低置信度结果 |
| `get_ocr_text_blocks(device, retries=2)` | `utils.py` | 使用 u2 截图并 OCR，外层重试过渡帧/空白页 |
| `adb_screencap(device)` | `utils.py` | 通过 ADB 截图，失败回退 u2 截图 |
| `get_ocr_text_blocks_adb(device, retries=2)` | `utils.py` | ADB 截图 + OCR，用于需要绕过 u2 覆盖层的页面 |
| `simple_ocr_region(d, x1, y1, x2, y2, keyword)` | `utils.py` | 区域内搜索关键词 |

## 返回数据结构

```python
[
    {"text": "去完成", "cx": 1018, "cy": 1450, "conf": 0.92},
    {"text": "浏览精选推荐30秒", "cx": 460, "cy": 1452, "conf": 0.88}
]
```

脚本通常用 `cx/cy` 做按钮邻近匹配，用 `text` 做任务类型和黑白名单判断。

## 与 U2 的分工

| 场景 | 优先方案 |
|---|---|
| 原生控件文本、按钮、可点击节点 | `uiautomator2` / `scan_page()` |
| WebView 中 U2 抓不到的文字 | `get_ocr_text_blocks()` |
| u2 截图受覆盖层影响 | `get_ocr_text_blocks_adb()` |
| 固定图标/关闭按钮 | OpenCV 模板匹配 |
| 已实测固定交互 | 坐标盲点法 |

## OpenCV / 图像辅助

## 关键策略

### 任务按钮扫描

`u2_find_task_buttons()` 的当前策略：

1. 优先按任务关键词找文本，如浏览精选、看直播、看视频、猜价格、省钱、上新好物等。
2. 将按钮 X 坐标估算为屏幕宽度 `0.84`，Y 坐标取任务文本中心。
3. 找不到时回退扫描“去完成/去浏览/去观看/去领取”等按钮文本。
4. 仍找不到时解析 hierarchy XML。
5. 按 Y 轴或坐标网格去重。

### 浏览任务

`execute_browse_task()` / `browse_task()` 的核心逻辑：

- 进入页面后立即先滑一次，减少等待。
- 检测“滑动浏览XX秒”并提取秒数。
- 文案消失且已满足最小秒数后判定完成。
- 未检测到滑动文案时按 `min_duration` 固定浏览。
- 同时检测“恭喜完成任务/任务完成/获得奖励”等提示。

### 直播/视频任务

- 自动从任务名解析秒/分钟，默认 120 秒并追加缓冲。
- 直播每 5-10 秒随机上滑，视频每 2-4 秒快速翻页。
- 若检测到“XX秒后完成”倒计时，倒计时文案消失即可提前完成。
- 持续尝试关闭弹窗，但通过冷却和关键词控制降低误点。

### 返回任务页

`back_to_task()` 先检测是否已在目标页，再点击关闭/返回/再逛逛等文本，最后按系统返回键；多次失败时可调用导航回调重进任务页。
