# 点淘自动化大管家

整个项目的业务任务已统一接入大管家看板：

- **常用流程**：点淘一键全部执行、连通性与下滑、日常任务、执行已保存的任务配置。
- **独立任务**：原 `task_catalog.py` 中全部业务任务，包括养优惠、签到、睡觉、走路、购物、摇一摇、钻石、主播、打工、赚钱卡及活动任务。
- **赚能量**：原 OCR 版及 WorkBuddy 截图 JSON 识别版。
- **其他现有入口**：AI 下滑和连通性检查。调试、截图、校准工具不列为手机业务任务。

双击根目录 **`启动大管家.cmd`**；原 `启动工作台.cmd` 同样进入完整项目看板。
手机扫码连接、任务搜索、启动/停止、实时日志、墨绿/黑/白配色均集成在同一桌面窗口。
扫码连接只建立连接，不会自动启动任务。同一时间只允许一项任务控制手机。
首页常用流程调用原 `一键全部执行.py` 串行执行点淘日常任务，不会同时启动全部脚本。
`执行已保存的任务配置` 沿用原 `task_config.json`；仍可使用原 `任务选择器.py` 编辑。
外部淘宝 618 脚本缺失时保留入口并标明原因，禁止启动；季节性任务的效果取决于对应活动是否仍开放。

迁移只调整入口，不移动任务脚本、图片资源、`.env`、任务配置或运行记录。
原命令行脚本和选择器继续可用；需要回退时可直接使用原入口。

## 首次准备

适用环境：Windows 10/11；手机扫码配对需要 Android 11 或以上。

1. 下载完整仓库并解压，安装 [uv](https://docs.astral.sh/uv/getting-started/installation/)。
2. 安装 Google 官方 [Android SDK Platform-Tools](https://developer.android.com/tools/releases/platform-tools)。
   将其目录加入 `PATH`，或在本机配置中填写 `DIANTAO_ADB_PATH`。
3. 双击根目录 `配置本机.cmd`，在 `%LOCALAPPDATA%\DianTao\config.env` 中
   填写自己可用的 `DIANTAO_OCR_SERVER_URL`。首次可导入旧 `.env`，不会覆盖已有配置。
   地址应包含 `/predict_ocr` 路径；接口契约见 [`cloud_ocr.py`](../cloud_ocr.py)。
4. 双击根目录 **`启动大管家.cmd`**。首次启动会建立专用环境并下载依赖，需要联网；后续直接复用。

OCR 服务地址、ADB 路径和配对信息不随仓库分发。没有配置 OCR 服务时，仍可打开工作台和扫码连接，
但启动 OCR 任务会提示先完成配置。WorkBuddy 能量版不要求云 OCR 地址，需另行安装并登录 WorkBuddy，
其识别配置沿用项目现有说明。本工作台不安装本地 OCR 大模型，也不要求独立显卡。
配置修改后重新打开工作台。以后换新版解压目录仍复用外部配置，不需要重新填写。

## 手机扫码

1. 手机和电脑连接同一 WiFi；访客网络的设备隔离会阻止连接。
2. 手机打开“开发者选项 → 无线调试 → 使用二维码配对设备”。
3. 点击工作台唯一的“扫码连接手机”入口，扫描显示的二维码。
4. 配对和连接成功后，关闭扫码窗口，选择一个任务启动。

不要使用微信或普通相机扫码。手机关闭无线调试、重启或网络变化后，可能需要重新开启无线调试。
若网络不支持 mDNS 发现，可使用 Android 官方的配对码方式在命令行配对，再返回工作台。

## 运行与停止

- 任务日志保存在本机 `.runtime/workbench/`；配色保存在本机 WebView 配置中。
- 任务使用同一个专用 Python 环境，点击任务时不再临时解析、下载依赖。
- 日志中的“运行中”表示进程存在；是否到账仍由各脚本的任务复查结果决定。
- 页面或授权状态不符合脚本要求时，脚本会停止并留下原因，不把未完成误报为成功。
- 点击“停止”会终止该任务的进程树；关闭桌面窗口也会停止它启动的任务。
- 原 OCR 与 WorkBuddy 能量版各有独立入口，其他任务沿用各自原脚本的识别方式。

## 打工任务守护

独立入口名称为 **打工任务**。启动后持续运行，点击“停止”结束：

- 进入打工页先扫描；打工中按剩余时间安排检查，不会重置两小时。
- 出现“领取888元宝”时领取，并执行奖励弹窗里的“去完成”；确认返回打工页后选厨师、开始打工，核对两小时倒计时。
- 每次进入顺便领取左侧“领体力”，领取后重新读取它的独立倒计时。支持秒级到三小时；两项中较早到期的一项唤醒守护。
- 暂时无法截图、OCR 或导航时逐步延长重试间隔；遇到未知页面或未支持的奖励任务则停止并保留现场。
- 重启会重新扫描手机当前状态；下一次检查时间保存在本机 `.runtime/dagong_guard/state.json`。

这个长期任务不加入 `task_catalog.py`、已保存批量配置或一键任务队列。当前版本沿用工作台的单任务启动限制，
与其他脚本之间的暂停、让路和恢复机制留待后续实现。独立运行时需要电脑与手机保持连接。

命令行也可运行 `python 打工任务.py`；加 `--once` 只处理一轮并输出下一次检查时间。
使用另一套“自动化大管家”时，运行 `python deploy/register_work_guard.py <大管家目录>` 注册独立入口，
再在大管家同步脚本配置；注册不会启动守护。

## 开发验证

```powershell
uv sync --project workbench --python 3.11
uv run --project workbench python -m pytest tests/test_workbench.py tests/test_workbench_desktop.py tests/test_workbench_ui.py tests/test_one_click.py tests/test_one_click_all.py -q
```

开发时可仅启动本机 Web 预览；不会自动执行手机任务：

```powershell
uv run --project workbench python -m uvicorn workbench.app:app --host 127.0.0.1 --port 9060
```
